FlyRank Machine Learning Capstone

Ranking Content Pages for Proactive SEO Review

A time-aware machine learning study for Refresh / Content Opportunity Scoring using pseudonymized search-performance signals.

Pink Sawda Nawar · Machine Learning Track

Abstract

This project asks which existing content pages should be prioritized for human review before they experience a meaningful decline in search visibility. I aggregate pseudonymized FlyRank search-performance data into monthly page-level features and use impressions, clicks, CTR, average position, and measured-data days to estimate next-month decline risk. A Random Forest is compared with a simple interpretable low-CTR-for-position baseline using time-aware development, validation, and final holdout periods. On the final May → June holdout, the model achieved Precision@50 of 0.620 compared with 0.360 for the baseline, while ROC-AUC improved from 0.470 to 0.614. The output is therefore presented as a ranked decision-support queue for human content review, not as proof that a page must be refreshed or that any feature causes Google ranking changes.

1. Introduction & Problem Statement

Content and SEO teams may manage thousands of pages while having limited time to inspect them manually. Treating every page equally can waste effort, while waiting until a serious traffic decline becomes obvious may delay useful investigation.

The research question is: Which existing content pages should be prioritized for review based on observable search-performance signals?

The decision supported by this work is a ranked review queue. Higher-risk pages can be inspected first for possible CTR problems, content relevance, search-position changes, or other issues. The system does not automatically prescribe a refresh.

2. Data

The project uses the gated FlyRank ML Internship warehouse hosted on Hugging Face. The main source is the fact_content_daily_performance table, aggregated from daily pseudonymized page-level observations into monthly page-level features.

3. Methodology

Features

The final model uses five feature-month signals:

  • Impressions per measured day
  • Clicks per measured day
  • CTR
  • Average search position
  • Number of days with usable GSC data

Outcome proxy

A page is marked declined_next_month = 1 when its impressions per measured day in the following month are at least 20% lower than during the feature month.

This is a practical review-priority proxy. It does not establish that a content refresh is necessary or that refreshing the page would reverse the decline.

Baseline

The baseline is an interpretable low-CTR-for-position rule. Pages receive higher priority when they have search visibility but CTR below a simple position-based expectation.

Machine learning model

The primary model is a Random Forest classifier with 200 trees, maximum depth 8, minimum leaf size 20, balanced class weights, and a fixed random seed.

Validation design & leakage control

March → April is used for development. April → May is used for model validation. Only after the features and hyperparameters are fixed is the May → June holdout opened. Future-month values are used only to construct labels and never as predictive inputs.

5. Limitations & Honest Framing

The final holdout performs better than the baseline but substantially below the validation Precision@50. This means the validation number should not be treated as guaranteed future performance.

The decline label is only a proxy. Lower future impressions can be related to changing demand, seasonality, ranking movement, competition, measurement availability, or other unobserved factors.

The study focuses on pages with measurable GSC data and at least 100 feature-month impressions. Findings therefore may not generalize to new or extremely low-visibility pages.

Interpretation boundary: this research provides observed, directional decision-support. It does not prove Google's ranking algorithm and does not prove that refreshing a page will cause performance to improve.

6. Ranked Recommendations & Action Playbook

The final model produces a public-safe ranked review queue. Higher scores indicate higher estimated risk of satisfying the future-decline proxy.

Action framework

REVIEW_NOW Very high predicted risk. Investigate the page immediately.

REVIEW_SOON Elevated predicted risk. Add the page to the next content-review cycle.

MONITOR Lower model risk. Continue observing unless other business context suggests intervention.

What reviewers should inspect

  • CTR relative to current search visibility
  • Recent search-position changes
  • Whether the content still matches user intent
  • Metadata/title opportunities
  • Whether falling impressions reflect demand rather than content quality

In the final queue, the highest-ranked examples were primarily associated with the reason code LOW_CTR_WITH_VISIBILITY. These reason codes explain why a page deserves inspection; they do not automatically prescribe a refresh.
